**Time‑complexity analysis**

```python
def strStr(self, haystack: str, needle: str) -> int:
    for each in range(len(haystack)):
        if needle in haystack[each:each+len(needle)]:
            return each
    return -1
```

Let  

* `n = len(haystack)`  
* `m = len(needle)`

| Step | What happens | Cost (worst‑case) |
|------|--------------|-------------------|
| `for each in range(len(haystack))` | The loop can iterate `n` times (if `needle` is never found). | `O(n)` iterations |
| `haystack[each:each+len(needle)]` | Python creates a **new slice** of length up to `m`. Slicing a string copies the characters, so the cost is `O(m)`. | `O(m)` per iteration |
| `needle in <slice>` | The `in` operator for strings performs a substring search. In CPython the implementation uses a fast two‑way algorithm, which is `O(k+m)` where `k` is the length of the slice (here `k ≤ m`). In the worst case (e.g., `haystack = "aaaaa…a"` and `needle = "aaaab"`), it degrades to the naïve comparison, i.e. `O(k·m) = O(m²)`. For a high‑level interview analysis we usually assume the naïve bound `O(m)` for the search on a slice of length `m`. | `O(m)` (or `O(m²)` in pathological cases) per iteration |

Putting the per‑iteration costs together:

* Per iteration: `O(m)` (slice) + `O(m)` (membership test) = **`O(m)`**  
* Number of iterations: at most `n`

Hence the **overall worst‑case time complexity** is  

\[
\boxed{O(n \cdot m)}
\]

(If we take the very pathological behaviour of the `in` operator into account, the bound can be as bad as `O(n·m²)`, but the standard interview answer is `O(n·m)`.)

The **space complexity** is `O(m)` because each iteration creates a temporary slice of length `m`.

---

### Why this is not optimal

* The algorithm repeatedly creates a new slice of the haystack – that copying alone already costs `Θ(m)` each time.
* The naïve scan checks every possible start position even after many characters have been matched, leading to the quadratic product `n·m`.

---

## Optimized solutions

### 1. Use the built‑in `str.find` / `str.index`

Python’s standard library already implements a highly‑optimized substring search (Boyer‑Moore‑Horspool / two‑way algorithm). Its average‑case complexity is linear, and the worst‑case is `O(n+m)`.

```python
def strStr(self, haystack: str, needle: str) -> int:
    """
    Returns the first index of `needle` in `haystack` or -1 if not found.
    Runs in O(n + m) time using the CPython implementation.
    """
    if not needle:                # empty needle -> defined as 0
        return 0
    idx = haystack.find(needle)   # C‑level implementation
    return idx if idx != -1 else -1
```

*Time complexity*: `O(n + m)` (linear).  
*Space complexity*: `O(1)` (no extra copies).

### 2. KMP (Knuth‑Morris‑Pratt) – pure Python, guaranteed linear time

If you need a pure‑Python implementation (e.g., for an interview where library calls are disallowed), the KMP algorithm builds a **prefix table** in `O(m)` and then scans the haystack in `O(n)`, giving overall `O(n + m)`.

```python
def strStr(self, haystack: str, needle: str) -> int:
    """
    KMP implementation: O(n + m) time, O(m) auxiliary space.
    """
    n, m = len(haystack), len(needle)
    if m == 0:
        return 0

    # ---- 1️⃣ Build longest‑prefix‑suffix (LPS) table for needle ----
    lps = [0] * m          # lps[i] = length of the longest proper prefix
                          # which is also a suffix for needle[:i+1]
    length = 0             # length of previous longest prefix suffix
    i = 1
    while i < m:
        if needle[i] == needle[length]:
            length += 1
            lps[i] = length
            i += 1
        else:
            if length != 0:
                length = lps[length - 1]   # fall back in the pattern
            else:
                lps[i] = 0
                i += 1

    # ---- 2️⃣ Scan haystack using the LPS table ----
    i = j = 0               # i -> index in haystack, j -> index in needle
    while i < n:
        if haystack[i] == needle[j]:
            i += 1
            j += 1
            if j == m:                # full match
                return i - j
        else:
            if j != 0:
                j = lps[j - 1]        # use previously matched prefix
            else:
                i += 1                # move forward in haystack

    return -1
```

*Time complexity*: `O(n + m)` (building LPS + scanning).  
*Auxiliary space*: `O(m)` for the LPS array.

### 3. Rabin‑Karp (rolling hash)

Another linear‑expected‑time method is Rabin‑Karp, which uses a rolling hash to compare substrings in `O(1)` average time. It also runs in `O(n + m)` expected time and `O(1)` extra space (aside from the hash variables).

```python
def strStr(self, haystack: str, needle: str) -> int:
    n, m = len(haystack), len(needle)
    if m == 0:
        return 0
    if m > n:
        return -1

    base = 256                # number of possible characters
    mod = 10**9 + 7           # large prime to avoid overflow

    # Compute hash of needle and first window of haystack
    needle_hash = 0
    window_hash = 0
    power = 1                 # base^(m-1) % mod
    for i in range(m):
        needle_hash = (needle_hash * base + ord(needle[i])) % mod
        window_hash = (window_hash * base + ord(haystack[i])) % mod
        if i < m - 1:
            power = (power * base) % mod

    for i in range(n - m + 1):
        if needle_hash == window_hash:
            # hash match → verify to avoid false positive
            if haystack[i:i+m] == needle:
                return i
        if i < n - m:
            # roll the hash: remove leading char, add trailing char
            window_hash = (window_hash - ord(haystack[i]) * power) % mod
            window_hash = (window_hash * base + ord(haystack[i + m])) % mod
            window_hash = (window_hash + mod) % mod   # keep positive

    return -1
```

*Time complexity*: Expected `O(n + m)`, worst‑case `O(n·m)` only when many hash collisions occur (rare with a good modulus).  
*Space*: `O(1)`.
