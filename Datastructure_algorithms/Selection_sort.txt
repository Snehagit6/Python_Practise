**Time‑complexity analysis**

The function implements the classic **selection sort** algorithm.

```python
for i in range(len(l) - 1):          # outer loop
    min_index = i
    for j in range(i + 1, len(l)):  # inner loop
        if l[j] < l[min_index]:
            min_index = j
    l[i], l[min_index] = l[min_index], l[i]   # one swap
```

| Step | How many times it is executed |
|------|------------------------------|
| Outer loop (`i`) | `n‑1` times (`n = len(l)`) |
| Inner loop (`j`) | For each `i` it runs `n‑i‑1` times → total = Σ₍i=0₎ⁿ⁻² (n‑i‑1) = (n‑1) + (n‑2) + … + 1 = **n(n‑1)/2** |
| Comparison `l[j] < l[min_index]` | Exactly the same number as inner‑loop iterations → **Θ(n²)** |
| Swap `l[i], l[min_index]` | At most `n‑1` swaps → **Θ(n)** |

Hence:

* **Worst‑case, average‑case, best‑case time complexity**  
  \[
  T(n) = Θ\!\left(\frac{n(n-1)}{2}\right) = Θ(n^2)
  \]
  In Big‑O notation we write **O(n²)**.

* **Space complexity** – The algorithm works **in‑place** and uses only a constant amount of extra variables (`min_index`, `i`, `j`).  
  \[
  S(n) = O(1)
  \]

---

### Why selection sort is *quadratic*

Selection sort always scans the *unsorted* portion of the list to find the smallest element.  
The size of that unsorted portion decreases by exactly one after each outer iteration, but the scan itself still touches almost every remaining element. The total number of element‑to‑element comparisons therefore grows proportionally to the sum of the first `n‑1` integers, i.e. `n(n‑1)/2`, which is Θ(n²).

---

## Possible optimizations

* **Algorithmic improvement** – Selection sort’s Θ(n²) behavior cannot be significantly improved without changing the algorithm. If you need a faster general‑purpose sort, use Python’s built‑in `list.sort()` (or `sorted()`), which implements **Timsort** and runs in **O(n log n)** time on average and in the worst case.

* **Minor code tweaks** – The inner loop can be written with `enumerate` for readability, but the asymptotic cost stays the same.

```python
def selection_sort(l):
    """Return a new list sorted with selection sort (O(n²) time)."""
    a = list(l)                # work on a copy if you want to keep the original
    n = len(a)
    for i in range(n - 1):
        # find index of the smallest element in a[i:]
        min_index = i
        for j in range(i + 1, n):
            if a[j] < a[min_index]:
                min_index = j
        # swap only if needed (saves a trivial assignment)
        if min_index != i:
            a[i], a[min_index] = a[min_index], a[i]
    return a
```

* **When to keep selection sort** – It has the nice property of making **at most `n‑1` swaps**, which can be advantageous when swaps are extremely expensive (e.g., when sorting large records on disk). Otherwise, for normal in‑memory data, prefer `list.sort()`:

```python
def timsort_sort(l):
    """Fast, stable O(n log n) sort using Python's built‑in algorithm."""
    return sorted(l)          # or l.sort() to sort in place
```
